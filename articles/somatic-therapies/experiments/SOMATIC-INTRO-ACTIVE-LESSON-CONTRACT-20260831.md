## Active lessons

### A1 — semantic obligations must not become rhetorical cards

**Trigger:** any reconstruction from a semantic/function checklist.

**Required behavior:** several obligations may live inside one developing thought; obvious relations may remain implicit. Preservation requirements stay in the background rather than determining sentence/paragraph topology.

**FAIL if:** consecutive sentences/paragraphs can be mapped mostly one-to-one to the supplied semantic requirements in roughly supplied order without chronology/causality requiring it.

**Repair:** discard the realization and reconstruct. Do not shuffle cards or add conversational surface.

**Enforcement:** semantic + owner-evaluated.

### A2 — conversational surface is not architectural change

**Trigger:** every generated candidate.

**Required behavior:** thought movement itself must differ from the known model essay architecture.

**FAIL if:** the passage remains proposition → qualification → explanation/closure, setup → qualification → conclusion, or another familiar mini-essay beneath contractions, first person, shorter sentences, fragments, or casual vocabulary.

**Repair:** reconstruct the movement; do not synonym-edit.

**Enforcement:** semantic + owner-evaluated.

### A3 — no over-completed explanatory packaging

**Trigger:** every generated candidate.

**Required behavior:** stop after the next necessary move. Let the reader make implications that do not require explanation.

**FAIL if materially present:** balanced contrasts organizing the section; readiness rendered as a tidy checklist; conditional responses rendered as a menu/taxonomy; a disclaimer explaining that the menu is not sequential; significance staging; polished cross-domain bridge; paragraph-level recap/diagnosis; equalized paragraph completeness; explicit synthesis after the relation is already apparent.

**Repair:** remove/reconstruct the packaging without dropping protected meaning.

**Enforcement:** semantic + owner-evaluated.

### A4 — owner correction is new cognition, not line-edit feedback

**Trigger:** Joel rejects or corrects an attempt.

**Required behavior:** persist the exact objection, identify the generative mistake, and make the next attempt from the semantic authority plus the new cognition.

**FAIL if:** the next candidate preserves the rejected draft's sentence/paragraph architecture and mainly substitutes wording.

**Repair:** discard the rejected realization and reconstruct.

**Enforcement:** process + semantic.

### A5 — model-only critique is secondary

**Trigger:** when the model believes it has repaired a failure Joel has repeatedly identified better than models have.

**Required behavior:** use self-critique only to catch obvious regressions; return one useful candidate to Joel rather than launching autonomous critique/rewrite loops.

**FAIL if:** the process substitutes repeated same-model writer/critic cycles for the manual Joel↔Chat loop or delays owner evaluation to run them.

**Repair:** stop the autonomous loop and return to one-attempt owner feedback.

**Enforcement:** process.

### A6 — preservation is a gate after realization, not a composition outline

**Trigger:** every candidate.

**Required behavior:** all semantic/function, attribution, certainty, actor, link, and scope requirements must survive, but preservation review occurs after the natural realization.

**FAIL if:** missing obligations are restored by appending a catch-up sentence/list/paragraph, or the preservation inventory visibly determines the prose sequence.

**Repair:** put the missing function back into the thought and reconstruct the affected movement.

**Enforcement:** semantic.

### A7 — no donor prose or fabricated humanity

**Trigger:** all humanization/detector work.

**Required behavior:** use only source material independently authorized for the exact Somatic function.

**FAIL if:** prose imports unrelated Joel/Pangram-Human/external human syntax, invented autobiography, fake chronology/specificity, random roughness, typos, slang, or rhetorical devices merely to affect detector behavior.

**Repair:** remove contamination and reconstruct from authorized meaning.

**Enforcement:** provenance + semantic.

### A8 — current known Somatic failure must not recur

**Trigger:** Somatic Introduction specifically.

**FAIL if the candidate again contains the prior failed package:** opening judgment → qualification → polished mind/body contrast; a three-part readiness checklist → verdict; regulation/bodily-resolution/EMDR menu → sequencing disclaimer; polished inner-child transfer → tidy distinction/resolution.

The literal wording may differ. This check concerns the hidden package.

**Repair:** reject before Joel sees it.

**Enforcement:** semantic + owner-evaluated.

Before showing Joel any new Introduction candidate, the Chat writer must privately execute this receipt against the **literal candidate**:

```text
A1 semantic obligations not rhetorical cards: PASS / FAIL — evidence
A2 architectural change, not casual surface: PASS / FAIL — evidence
A3 no over-completed packaging: PASS / FAIL — evidence
A4 latest owner correction actually changed realization: PASS / FAIL / N/A — evidence
A5 manual Joel↔Chat loop preserved: PASS / FAIL
A6 preservation did not become outline/catch-up: PASS / FAIL — evidence
A7 source-integrity/no fabricated humanity: PASS / FAIL
A8 known Somatic failed package absent: PASS / FAIL — evidence
Contract freshness after latest Joel correction: CURRENT / STALE
ADMISSION: ADMITTED / BLOCKED
```

Any substantive FAIL or STALE blocks delivery. Repair/reconstruct first and rerun the receipt.

`I read the lesson`, `I remembered it`, or `the prompt said not to do it` is not a PASS. The evidence must be about the literal candidate/process.

## After Joel responds

If Joel gives a substantive new correction:

1. persist it immediately in `SOMATIC-MANUAL-HUMANIZATION-WRITER-STATE-20260831.md` with the underlying generative mistake;
2. update this active contract if the correction creates or changes an enforcement condition;
3. mark the old contract stale until that is done;
4. only then write the next attempt.

This is the intended loop:

**lessons stored → relevant lessons activated → one Chat attempt → admission gate → Joel evaluates → correction stored → contract refreshed → next attempt.**

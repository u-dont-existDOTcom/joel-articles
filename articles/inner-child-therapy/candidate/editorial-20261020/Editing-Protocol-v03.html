# Structural deduplication and sequencing — execution v0.3

Status: the v0.1 principles were accepted in Joel’s 2026-10-19 owner-review answers. The v0.2 scope, sequencing, visual-review and enforcement corrections are retained. This v0.3 applies the owner’s terminal 2026-10-19 review: execute basic copy repairs, keep valid reader-facing introductions, and interpret approval together with specified revisions. These corrections are owner-directed; performance/generalization is not thereby established. Neither approval of the rules nor a passing package check establishes improved editing performance. Owner request: 2026-10-19, Intentional Communities comparison. This file adds execution steps to the existing rules; it does not replace preservation, source authority, voice, scope, media, or publication controls.

## Trigger and objective

Use for article-wide deduplication, consolidation, streamlining or sequencing under an authorized developmental-edit scope (P3). For a report-only request, perform the diagnosis without changing the article. Do not escalate an ordinary P1/P2 edit into a developmental rewrite.

A request to merge sections while changing as little wording as possible has two compatible requirements: repair the organization, then minimize rewriting inside the chosen organization. It does not require preserving every heading, paragraph boundary or duplicate explanation. Judge success by the reading experience and necessary content retained, not by words deleted or the number of sections merged.

## 1. Read the whole article before selecting cuts

Freeze the exact source and owner constraints. Establish its audience, promise, intended payoff and the job of its strongest existing material. Use the existing multiscale ledger: a compact reverse outline of what each section/paragraph contributes, not a sentence-by-sentence preservation bureaucracy. For a long article, inspect every section; flagged passages set priorities, not the audit's boundary.

Keep content authority and explanatory packaging separate. Protect independent claims, limitations, decisions, distinctive examples, jokes and personal material. Do not create a protected proposition for every paraphrase or unpacking of the same thought. Never infer a new experience or author belief from an edit that would improve the prose.

## 2. Group overlaps before editing them

Gather all passages that answer the same reader question or perform substantially the same explanation. Inspect the union, including unflagged passages. For each meaningful overlap cluster record:

- its primary explanatory home and why the reader needs it there;
- the distinct information or rhetorical effect contributed by each occurrence;
- the exact passages to move, merge, shorten, retain or remove;
- the surviving destination of each independent contribution.

When overcompletion may contain an independent claim or procedure—especially in a draft built from AI research—ask the owner about the intended scope, using the exact passage and a specific retain/condense/relocate choice. AI origin is not deletion authority. Keep that content while the question is unresolved; do not turn every obvious duplicate into a new approval request.

A paragraph containing one useful sentence need not survive whole. Move that sentence or qualification into the strongest surviving treatment. Prefer a genuinely integrated passage over concatenating all the old paragraphs below a new heading. A list of ten examples is not automatically ten independent points; preserve the distinctions and those examples that earn their space. An example with unique argumentative or personal value remains protected.

## 3. Test a whole-article route

Read the reverse outline independently of the current order. Ask what the reader needs to understand, see, believe or be able to do before the next section. Distinguish a real prerequisite from an editorial preference. Consider where the strongest concrete example belongs, where practical action first becomes possible, and where the article changes between a person, one group and a wider movement.

When the order is materially uncertain, or local trimming has failed to solve the same global problem, compare the retained order with at least one genuinely different source-supported route before more line editing. Choose the better route within the owner's authority; expose only material taste/meaning tradeoffs. Do not make every essay obey a fixed sequence such as problem→example→instructions. Do not postpone all useful action until a ceremonial conclusion by default.

### Reader decisions, argument and conceptual order are different

Map what a reader needs to decide, and what each section enables. Distinguish (a) a prerequisite to understanding the next passage, (b) a prerequisite to taking an action, (c) an argument–counterargument or problem–antidote pair, and (d) an optional cross-reference. A conceptual list is not automatically a chapter sequence, and reading about an activity early does not authorize doing it before its stated prerequisites. Keep a distinctive, owner-identified reason to read visible rather than burying it beneath generic process detail.

When plausible routes compete, compare them on the actual audience, promise, decision progression, important adjacencies, reference burden and cognitive load. Use no invented numerical quality score. Resolve ordinary choices yourself; ask only when changing the audience, promise, position or scope would appropriate an authorial decision.

### Keep the visual outline synchronized with the literal text

For substantial resequencing advice or delivery, provide an interactive before/after diagram. It must show section and subsection purposes, meaningful dependencies, exact old/new locations, and the pros and cons of the selected route. Default to a readable overview; reveal connections when a section is selected instead of drawing every edge at once. Link a node to its actual text, not merely a remembered title.

Generate the heading tree from the current candidate and maintain editorial purposes alongside stable source IDs. After each assembly, check the diagram against the literal headings, parents and passage locations. The map describes the prose; it must not become an obsolete outline or a compulsory sentence-writing template. An operation comment belongs to the move/consolidation relation shared by both sites.

## 4. Implement the smallest wording change that completes the chosen edit

Prefer intact movement, removal of duplicated wording, local joining, then fresh connective wording where needed. A small bridge is justified when it expresses a relation already supported by the source. It is not permission to add a new claim, decision rule, personal history or a more defensible position.

### Preserve real introductions; repair small errors without making them owner decisions

A reader-facing orientation is not private editorial chatter just because the author says what the section will discuss. Before deleting an opener, identify the question or expectation it establishes and what would open the section without it. Keep an introduction that announces a genuinely needed value/risk discussion. Do not mechanically cut all meta-language under an anti-aftercare rule.

When the article explains why a neglected topic belongs, preserve its public relevance before the author's personal-model rationale when that is the intended argument. Moving the real-world problem behind “my model needs it” can make the rationale appear circular. Repair the order rather than rewriting the author's convictions.

Execute obvious missing-word, agreement, duplicate-token and similarly unambiguous copy repairs within the current edit permission; disclose them briefly, but do not ask for repeated approval of each basic fix. Preserve unusual deliberate diction and genuine semantic choices. A newly written bridge is still new prose: apply the current voice/humanization rules to it, and never inherit a green detector score from surrounding untouched text. When the owner supplies the replacement, use that wording with only authorized basic repairs.

After each consolidation inspect both the vacated position and the destination. Repair referents, sequence words, headings, numbering, promises, source links and media anchors. Move an image or caption with its semantic purpose, not mechanically with the nearest paragraph. Keep required notices available where the reader must act on them.

In a source-only replay, preserve every distinct link destination unless its removal has separate authority. A shorter link-bearing passage may carry its link in the surviving discussion; moving the link to an unrelated word is not preservation. In a live owner revision, the owner's deletions control and are not resurrected just to match the old link count.

## 5. Make remaining repetition earn its space

Reuse the existing categories: setup, primary exposition, application, payoff/callback, true duplicate. A label alone is insufficient: specify the reader's new gain at this occurrence. A reminder may make a practical section independently usable, and deliberate repetition may provide rhythm or emphasis. Those are valid gains when visible in context.

Test the counterfactual: would replacing the second treatment with a short pointer, or combining both treatments at the main decision point, preserve everything important? If so, implement it within scope. If not, retain the separate treatment and record what would be lost. Similar vocabulary is neither proof of duplication nor a reason to invent new terminology.

## 6. Review the assembled article for sufficiency as well as fidelity

Read it consecutively, not just through the edit list. Ask a reader to identify the actual remaining re-explanations, unnecessary returns, overlong previews and repeated endings. Separately check whether a cut hid a condition, removed a useful distinction or made a later passage unintelligible. Use a genuinely fresh reader when available and required by the existing independent-reader rule; describe same-context review honestly.

A fidelity/media PASS does not mean the developmental task is complete. For every owner-flagged cluster, record resolved, partially resolved with an exact residual, or retained with a specific distinct function. Do not claim complete deduplication while a known large overlap is still unresolved. An arbitrary reduction target, clean diff, successful clipboard test or Pangram score cannot supply that judgment.

## 7. Freeze editorial decisions before detector repair and delivery

Use the existing detector and transfer rules. Unchanged exact tested boundaries retain their evidence; altered wording, order, paragraphing or relevant neighboring context needs its own detector status. Never use detector anxiety to preserve a known editorial defect, and never say a reordered passage still passes without evidence.

Deliver the current candidate, traceable old→new locations, important omissions/tradeoffs and any residual decisions. Use the canonical review/helper generators when those artifacts are due. Verify the delivered files themselves and give usable files, not repository navigation. For this workflow, use the artifact-binding and delivery checks in `EDITORIAL-EXECUTION-ENFORCEMENT.md`. A successful fidelity or clipboard check cannot substitute for the explicit article-wide repetition and sequencing judgment.

## 8. Learn without leaking the answer into the test

Classify an owner's revision as source-recoverable editing, source-supported but preference-dependent change, new owner material, or mixed. Split mixed changes at the actual meaning boundary. Exact before/after examples stay in the article's case study; the shared rule describes the transferable operation and its limits.

A fresh writer replay receives only the original source, frozen general rules and original permissions, not the target revision, its ordering, the case study, or a target-derived edit list. Freeze its output before comparison. Because rules learned from this article are tested on this article, that result is a development-set replay, not held-out generalization—even with perfect context isolation. Measure accepted editorial decisions recovered and remaining owner work; never infer minutes saved from deleted words. Use a different untouched article for generalization.

## Application receipt

Read terminal owner answers together with their final written qualifications. An “Approve” selection accompanied by “with revisions as specified” authorizes the specified revised result, not the unchanged candidate; keystroke history is evidence, not a list of independent edit requests. Preserve the raw export, apply its terminal decisions, and record each disposition.

Keep one compact receipt in the existing task state: source/authority; requested edit scope; major overlap clusters and their dispositions; order chosen and its reason; independent content lost/added and authority; remaining repetition; full-read result; detector/transfer status where due; reader independence; actual files delivered. This is evidence for review, not a replacement for making the edit.

# Editorial execution enforcement — implementation and limits

Status: implementation candidate for owner approval. The local gate and its service adapter are tested on the article package and deliberate failures. No new hosted service, global ChatGPT interception, managed Claude hook or protected-branch rule is claimed to be deployed.

## A failure diagnosis more precise than “execution failure”

The earlier passes show a chain of distinct problems. The exact original request allowed mergers while asking for restraint in wording. Repository rules already required global organization and primary homes for recurring ideas. Some retrievals displayed only prefixes; that is a possible exposure gap, not proof of what the model internally read. The delivered r02 still treated a three-way practice cluster as a two-way merger. Fidelity, word counts and derivative tests were reported without an equally specific remaining-duplication result. Those are observable scope and completion-evidence gaps. The retrospective explanation that preservation anxiety caused them remains an interpretation.

The repair therefore addresses different boundaries rather than adding another promise to “be a better editor.”

| Boundary | What changes | What this can actually establish |
|---|---|---|
| Task admission | Bind exact owner source, answer file, scope and source-specific constraints. | Prevent working against a different revision or an old answer set without detection. |
| Developmental reasoning | Read the whole article, inventory complete overlap clusters, compare reader routes and retain source/owner boundaries. | Produces inspectable editorial judgments; code cannot prove their quality. |
| Assembly | Keep stable IDs, exact edit chains, native islands and link counts; rebuild the heading tree from the candidate. | Detect missing blocks, undocumented changes, lost media, stale outlines and violated declared ordering. |
| Reader review | Keep full-read evidence and any subsequent delta rechecks bound to the exact versions reviewed. | Establishes what was reviewed and by which available route, not correctness or independent identity. |
| Artifact delivery | `editorial_gate.py package` runs the gate and refuses a mismatched or incomplete bundle before writing the ZIP. | The tested packaging route cannot silently produce the marked review package after those failures. Unrelated routes remain outside it. |
| Service-side finalization | `RegisteredService` resolves the server-enrolled task and contract, accepting only task ID and expected candidate hash. | Rejects client-supplied PASS/approval fields, paths, unknown tasks, stale enrollment and stale candidates. It uses the same gate as local packaging. |

## What the gate checks

The candidate must match its source/owner binding; every source top-level block must survive exactly once or have an exact authorized omission disposition; the candidate must equal the literal ledger assembly; each changed block must have an exact before→after edit chain. Whole-block consolidation/deletion is supported when its exact source ID, reason, authority reference and semantic-review disposition are recorded. Empty spacers can be verified mechanically. Current r03 uses no whole-block omissions; this is not a general command to preserve inherited paragraphs. Native source objects remain byte-identical, while their intentional new positions are tracked. The ordinary link destination multiset is unchanged.

The diagram must include every real heading in order, with the correct level and parent. Every heading has an editorial purpose and reader question. Source-specific hard constraints are data, not universal title rules: for this article, Founderism and Movement remain adjacent, readiness and membership share the Practice parent, commitments precede exit, values precede visiting advice, and the medicine heading loses its stray number.

Every independently inventoried overlap cluster needs a disposition for every known occurrence. A two-of-three accounting fails. Every reported move needs both vacated-location and arrival-location audit entries. Required forward references must occur in the actual passage and point forward to an existing target. Pending scope choices must still have their original content present.

A candidate-bound editorial review and explicit scope/limits are required. Known blocking defects cannot be hidden by a PASS label. Finally, each delivered artifact must match its registered hash, and the canonical transfer receipt must bind the exact candidate. `REVIEW_PACKAGE_READY` does not mean owner-approved, newly Pangram-certified, fact-checked, published or perfectly deduplicated.

## Which checks are judgments rather than code proofs?

Discovery of all conceptual duplicates, importance of a qualification, a section’s purpose, adequacy of a bridge and the quality of the chosen order remain language/authorial judgments. The gate checks completeness and identity of their recorded evidence. It cannot detect a confidently wrong but well-formed judgment, authenticate the reviewer from a model-written receipt, or prove that an undiscovered cluster does not exist.

That is why the package includes the actual source comparison and the fresh-reader scope, not just a ticked checklist. A local writer with filesystem access can alter a local contract; a meaningful production service must isolate registration and record-writing permissions from the client. This prototype rejects mutations after enrollment, but it is not an independently administered security boundary when both processes share one OS account.

## How server-side enforcement differs from a stronger prompt

AskRigor’s inspected finalization implementation verifies server-issued research receipts against the research target and returns explicit readiness states. The transferable feature is the location and provenance of the check: the model’s statement that it completed research is not the only evidence. Its source also explicitly leaves some semantic applicability and advice-quality declarations to the model. That is not a reason to call every server receipt a proof of judgment.

This editorial implementation adopts a smaller version appropriate to a local review package: a registered immutable contract, exact artifact identities, named review evidence, strict request schema and a blocked output operation. The localhost test demonstrates this adapter; it does not claim that AskRigor’s deployed authentication or signing system has been installed here.

## Stronger deployment options, not silently installed

Claude Code hooks can place a check at a supported tool or completion boundary; a hook only protects invocations that load it. A project-controlled packaging command is simpler to verify here than a global Stop hook that may obstruct unrelated work. Required GitHub status checks can protect merging, but only when the corresponding repository rule is actually enabled and the status itself tests the intended object. They cannot block a separate chat response or clipboard operation.

The recommended next deployment step, after approval, is to route each article delivery through the tested gate and verify the exact integration in the relevant client. A hosted service or managed hooks are justified when they close a demonstrated bypass, not as a substitute for better semantic judgment. This task has not modified other apps, provider configuration or global client settings.

## Current commands

Run `python editorial_gate.py check --bundle BUNDLE --phase editorial` before derivative preparation and `python editorial_gate.py package --bundle BUNDLE --out REVIEW.zip` for the final review archive. The latter requires the delivery artifact inventory and canonical helper receipt. The service adapter is exercised through the loopback HTTP regression in `test_editorial_gate.py`; it is not left running.

The same module is used for positive tests and deliberately corrupted copies. Failure cases include stale source/candidate/answers/review, missing third overlap occurrence, a missing map node, violated adjacency, lost native object, missing two-site audit, an altered artifact, client approval injection, traversal, stale server enrollment and changed bytes after enrollment. An unchanged legitimate package remains eligible. Test counts and exact outcomes are supplied separately; this text does not assert a result before the tests run.

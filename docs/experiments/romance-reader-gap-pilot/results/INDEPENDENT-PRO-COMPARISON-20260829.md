## Architecture decision

### Reader-question audit

**Validated as an optional diagnostic for broad long-form articles.**

Reasons:

1. It independently reproduced the deepest hidden cluster: workability, incompatibility, safety, and ending.
2. It discovered a material new candidate: sexual-fit trajectory.
3. It correctly recognized many delayed or distributed answers instead of labeling every question a gap.
4. It falsified or downgraded several hidden/external hypotheses.

### Obsidian Canvas

**Promising but not yet independently validated as necessary.**

The experiment validates durable question objects and typed answer relationships. It does not yet prove that Obsidian is better than a compact table/JSON report for owner review. Canvas earns continued testing only if it makes the small unresolved set easier for Joel to understand and decide.

### Recommended minimal production shape

Keep Mermaid as the required positive architecture map.

For a substantial publication-preparation pass, optionally run:

1. promise-first question freeze;
2. sequential blind-prefix checkpoints;
3. final hindsight coverage classification;
4. retain only:
   - `candidate`;
   - `unclear`;
   - a small set of answered controls;
   - externally supported questions kept explicitly separate from article-internal findings;
5. generate Canvas only from that reduced register.

Do not persist all transient checkpoint questions as permanent editorial tasks.

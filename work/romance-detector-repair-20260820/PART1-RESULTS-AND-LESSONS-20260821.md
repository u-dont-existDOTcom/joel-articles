## Exact-repeat recovery incident

During recovery, the r2 multi-variant result was initially only partially visible. The durable call ledger already contained paid reservations for the other variants, but the worker incorrectly inferred they were unspent and queued separate identical requests.

At least Affection and Crucible were actually submitted twice under different measurement keys: the same text SHA has two different Pangram task IDs. These are real duplicate paid tasks and remain counted; do not erase actual cost.

Root cause: the durable cache path is content-hashed but still contains a measurement-key filename, so a new measurement key can submit identical text while the first result is pending/not yet noticed. The runner previously had no same-audit/same-section exact-text reservation guard across measurement keys.

Repair on `pangram-humanization-lab:automation/pangram-fixed-batch`:

- `TrackedPangramClient` now blocks an exact text SHA that already has a paid/reserved measurement under the same audit section/model/version;
- fixed-batch variants may opt in only with explicit `allow_exact_repeat: true` for intentional preregistered replication;
- regression coverage added in `tests/test_tracked_pangram_repeat_guard.py`;
- a branch test workflow covers the repeat guard plus fixed-batch and call-budget tests.

Operational lesson: **result visibility is not call-state authority.** Before a recovery POST, inspect the durable call ledger and exact text SHA reservations, not merely whether the expected result file is currently visible.

## Transferable editorial lessons strengthened by Part 1

1. A red detector window is a clue; the natural section determines the current failure.
2. If two faithful paraphrases preserve the same failing architecture, version three should challenge the container/job rather than synonyms.
3. Comprehensive advice/checklists can erase the authorial pressure that generated the advice.
4. Lived contradiction or failed implementation can be the missing connective tissue: `here is my advice` becomes authorial when followed by `here is why I needed it / why I fail to follow it`.
5. Let concrete examples perform conclusions; abstract aftercare can be both redundant and detector-hostile.
6. Do not sacrifice protected safety or owner arguments to a local detector result; widen/restore natural context first.
7. Arbitrary article-half boundaries are not semantic sections.
8. Exact paid-work recovery must be keyed to durable reservation state plus text hash, not filenames, chats, or currently visible result artifacts.
